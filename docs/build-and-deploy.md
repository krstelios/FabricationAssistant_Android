# Building and Deploying to the Tablet via USB

End-to-end guide for getting the Android build onto a tablet over USB, from
zero to a running app + a log stream you can read.

---

## 1. One-time machine setup

### 1.1 Android SDK + platform-tools

The build script (`Android/tools/build.ps1`) requires `ANDROID_HOME` to point
at an Android SDK install. If it isn't set, the script falls back to
`%LOCALAPPDATA%\Android\Sdk` - so the easiest setup is to install Android
Studio once and let it drop the SDK there. After that you can close
Android Studio forever; the build doesn't need it.

`adb.exe` lives in `%LOCALAPPDATA%\Android\Sdk\platform-tools\`. Add that
directory to your PATH (or keep prefixing every `adb` invocation with the
full path).

### 1.2 JDK 17

The .NET Android workload's `ValidateJavaVersion` task can't parse JDK 21's
version string (it throws `XA0033` on every build). Install JDK 17 under
`%LOCALAPPDATA%\JDK17\` and `build.ps1` will pick it up automatically; any
other layout requires you to set `JAVA_HOME` yourself.

### 1.3 .NET 8 + the Android workload

```powershell
dotnet workload install android
```

### 1.4 USB driver

For Samsung tablets you need Samsung's USB driver
(<https://developer.samsung.com/android-usb-driver>). Other OEMs may need a
Google USB driver (<https://developer.android.com/studio/run/win-usb>) or
nothing at all. After install, the tablet should appear in
Device Manager as `Android Device > Android Composite ADB Interface`.

## 2. One-time tablet setup

1. Open Settings > About tablet > Software information
2. Tap "Build number" seven times until Developer Mode unlocks
3. Open Settings > Developer options
4. Turn ON "USB debugging"
5. (Optional but useful) Turn ON "Stay awake" so the screen doesn't sleep
   while plugged in
6. (Optional) Turn ON "Disable adb authorization timeout" so you don't have
   to re-approve every few days

When you plug the tablet into the workstation for the first time, a dialog
appears on the tablet asking "Allow USB debugging from this computer?" with
an RSA fingerprint. Tick "Always allow" and tap OK.

## 3. Per-session sanity check

```powershell
adb devices
```

Expected output:

```
List of devices attached
R52Y80CE37L     device
```

Troubleshooting if you see `List of devices attached` and nothing else:

| Symptom | Fix |
|---|---|
| No device shown at all | Re-plug the cable; some cables are charge-only. Try a different USB port (USB-3 ports on the front of the workstation are flakier than rear ports). |
| Device shown as `unauthorized` | Check the tablet for the RSA-fingerprint dialog and approve it. |
| Device shown as `offline` | `adb kill-server` then `adb start-server`. |
| Tablet not even recognized by Windows | Reinstall the Samsung/OEM USB driver. |

If `adb` itself seems stuck:

```powershell
adb kill-server
adb start-server
adb devices
```

## 4. Building

From the repo root (or anywhere - the script resolves paths from its own
location):

```powershell
.\Android\tools\build.ps1                      # Debug, restores, builds
.\Android\tools\build.ps1 -Configuration Release
.\Android\tools\build.ps1 -Clean               # clean first
```

What this does:

1. Resolves `ANDROID_HOME` (and warns if neither it nor
   `%LOCALAPPDATA%\Android\Sdk` exist)
2. Redirects `JAVA_HOME` to a JDK 17 install if it finds one
3. Builds `libdraco_native.so` for `arm64-v8a` and `x86_64` if the prebuilt
   `.so` files aren't already in `Android/deps/prebuilt/`
4. `dotnet restore` (skip with `-Restore:$false`)
5. `dotnet build Android/FabricationAssistant.Android.sln`

The signed APK lands here:

```
Android\src\FabricationAssistant.App.Android\bin\<Debug|Release>\com.fabricationassistant.android-Signed.apk
```

> Do NOT use `dotnet build` against the desktop solution from the repo
> root - it includes the C++/CLI `OcctBridge` project that the `dotnet`
> CLI cannot compile. Always go through `Android/tools/build.ps1` (or
> target the Android solution explicitly).

## 5. Deploying to the tablet

There's no single one-shot script - the standard sequence is three `adb`
calls.

```powershell
$apk = "Android\src\FabricationAssistant.App.Android\bin\Debug\com.fabricationassistant.android-Signed.apk"

# Stop any running instance first so the install doesn't bounce off a
# locked file in the data dir
adb shell am force-stop com.fabricationassistant.android

# -r reinstalls (preserves user data); add -d to allow downgrades
adb install -r $apk

# Launch MainActivity. The class name is auto-generated by Xamarin from
# the C# namespace+class hash, so this name is stable but odd-looking.
adb shell am start -n com.fabricationassistant.android/crc649abf7c96d03d876b.MainActivity
```

Quick uninstall if you need to wipe SharedPreferences / settings.json:

```powershell
adb uninstall com.fabricationassistant.android
```

### Streaming logs while you test

Clear the log buffer first so what you're about to see only contains the
fresh run:

```powershell
adb logcat -c
adb logcat -v color
```

Filter to just the Fabrication Assistant log tags + crashes:

```powershell
adb logcat -v color *:S FA.App:V FA.Renderer:V FA.Gles:V FA.Shader:V FA.Ssao:V FA.NormalDepth:V FA.MeshUpload:V AndroidRuntime:E DOTNET:V
```

For a one-shot dump of everything the app has logged since startup (works
even after a crash):

```powershell
$pid = (adb shell pidof com.fabricationassistant.android).Trim()
adb logcat -d --pid=$pid
```

If the app crashes at startup and `pidof` returns nothing, the crash trace
is in the crash buffer:

```powershell
adb logcat -b crash -d -t 100
```

That's where you'll see `FATAL EXCEPTION` + the C# stack trace for
managed exceptions (e.g. shader link failures bubble up as
`System.InvalidOperationException` from `ShaderProgram..ctor`).

For native (libc / EGL / driver) crashes:

```powershell
adb shell ls -1t /data/tombstones | head -3
adb shell cat /data/tombstones/tombstone_00
```

## 6. Iteration loop

The fastest dev cycle for a code change:

```powershell
.\Android\tools\build.ps1
adb shell am force-stop com.fabricationassistant.android
adb logcat -c
adb install -r "Android\src\FabricationAssistant.App.Android\bin\Debug\com.fabricationassistant.android-Signed.apk"
adb shell am start -n com.fabricationassistant.android/crc649abf7c96d03d876b.MainActivity
adb logcat -v color --pid=(adb shell pidof com.fabricationassistant.android)
```

For shader-only changes there's no shortcut - shaders are embedded as
assembly resources, so any edit to `Android/src/FabricationAssistant.Rendering.Gles/Shaders/*.gles.*`
still requires a full `build.ps1` + reinstall cycle.

## 7. Common gotchas

- **`dotnet sln add` is broken** on this workstation. Edit
  `Android/FabricationAssistant.Android.sln` manually when adding projects.
- **Avoid `2>&1` on native exes inside PowerShell.** PowerShell wraps each
  stderr line in an ErrorRecord and forces `$LASTEXITCODE`-equivalents to
  look like failure. Just let stderr go to the console.
- **`adb install -r` will refuse a downgrade.** Append `-d` (or
  `adb uninstall` first) if you're moving back to an older version.
- **Tablet's app PID can change** between runs; always re-read it with
  `pidof` rather than caching it.
- **Wireless adb is supported** (`adb tcpip 5555` then
  `adb connect <tablet-ip>:5555`) but the Mediatek tablets we test on tend
  to drop the connection after a few minutes; USB is more reliable.
- **The Activity name `crc649abf7c96d03d876b.MainActivity`** is the
  Xamarin-generated wrapper for `FabricationAssistant.App.Android.MainActivity`.
  If you ever change the C# class's namespace or name, the CRC suffix
  changes too and your `adb shell am start` command needs updating - grab
  the new name from
  `Android/src/FabricationAssistant.App.Android/obj/Debug/<tfm>/android/manifest/AndroidManifest.xml`.
