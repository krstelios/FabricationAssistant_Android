# Plan — Buttery 90 fps Android viewport

Branch: `perf/90fps-buttery`
Created: 2026-05-28

## Goal

Hold a stable **90 fps** (≤11.1 ms/frame) on the Galaxy Tab S11 Ultra with the
1751-mesh CAD test scene at full quality: MSAA 4×, SSAO on, edges on, outlines on.

Hard constraint: **do not break dimensioning.** Imported edges (line ribbons used
by the measurement tool), face/edge picking by `MeshIndex`, and the measurement
overlay must all continue to work.

## Starting point (already measured this session)

| pass | CPU ms | GPU ms (glFinish probe) |
|---|---|---|
| Total | 21.2 | (n/a — vsync) |
| SSAO | 6.7 | ~10 |
| Scene (surfaces + edges + overlays) | 14.0 | huge — stalls compound |
| &nbsp;&nbsp;↳ Edges | 5.4 | ~30 |
| Outline | 0.5 | <1 |

Need to save ~10 ms wall-clock to hit 90 fps.

## Phased approach

Each phase is shippable on its own. After each, measure with FA.FrameTiming +
spot-check with glFinish on the pass we changed. **Commit after every green
phase** so we can bisect regressions.

### Phase A — GPU timer queries via `EXT_disjoint_timer_query`

Replace the temporary `glFinish` instrumentation with async timer queries (Mali
and Adreno both support the extension). Ring-buffered, no pipeline stall, no
fps impact. Every per-pass timer in `FrameTimingAccumulator` becomes actual GPU
completion time.

**Risk:** low. Pure instrumentation. Falls back to CPU-only timing if the
extension is absent.

**Done when:** FA.FrameTiming reports a `gpuEdges=` (or similar) field with no
visible fps drop on the tablet.

### Phase B — CPU frustum culling

Per frame: derive 6 frustum planes from `view * projection`. For each mesh,
AABB-vs-frustum test on the cached `WorldBounds`. Skip both surface draw and
edge draw for invisible meshes.

For a typical CAD inspection workflow (zoomed into a sub-assembly) this can
skip 50-80% of meshes per frame.

**Risk:** low. `WorldBounds` already exists. The test is a few dot products
per mesh. Bug surface is small — wrong test means missing geometry, which is
visually obvious.

**Done when:** with the camera framed on a small sub-assembly, the per-frame
mesh draw count drops noticeably (verified via a new log field).

### Phase C — Screen-space silhouette hybrid (Tier 4 edges)

Split `CadEdgeBuilder` output into:
- **Always-on** stream: boundary + feature + imported edges. These include the
  dimension lines and CAD feature creases. Stays as instanced geometry.
- **Silhouette-candidate** stream: dropped from the VBO entirely.

Add a fullscreen post-process that reads `_normalDepthRenderer.NormalTexture`
and emits silhouettes via Laplacian zero-crossing on depth + normal first-
derivative (Antichamber-style — already researched). Composites over the
final framebuffer before outline.

**Risk:** medium. Silhouettes look pixel-snapped instead of ribbon-style, but
the visual change is small and the dimensioning code paths are untouched
(dimensions use imported/feature edges only, not silhouette candidates).

**Done when:** edges look right, silhouette segments removed from VBO upload,
edge timer drops measurably.

### Phase D — Draw-call batching

The biggest remaining lever. 1751 separate `glDrawElements` calls + ~7000
`glUniform*` calls per frame is the dominant CPU cost.

Approach:
1. Group meshes by `(program, material-class, transform-arity)` at upload
   time. Many CAD meshes share identical transforms and materials.
2. Per-group, build a **per-instance attribute buffer** (transform + color +
   mesh index) and switch to `glDrawElementsInstanced` for that group.
3. For groups with a single instance, fall back to the current path.
4. The mesh fragment shader needs a per-instance `MeshIndex` (for picking +
   selection highlight) — provide it via instance attribute.

**Risk:** higher. Touches the entire surface pipeline. Picking + selection +
outline post-process all consume `MeshIndex`. We have to preserve correctness
across all of those.

**Mitigation:** roll out incrementally — first do same-material groups, then
extend. Keep the single-instance fallback path so any regression is contained.
Pick a single highly-instanced material first (e.g. all standard-grey
surfaces) and verify before extending.

**Done when:** per-frame draw call count drops to <500, scene timer drops by
3-8 ms.

### Stretch phases (if A-D don't hit 90 fps)

- **Phase E:** MSAA 4× → FXAA post. Mali tile resolve is expensive bandwidth.
- **Phase F:** SSAO temporal accumulation (per-frame IGN jitter + history
  blend). Cuts SSAO from ~10 → ~4 ms GPU.

## Rollback strategy

Each phase commits independently with a clean before/after FA.FrameTiming log
saved to the commit message. To bisect regressions: `git log
perf/90fps-buttery` shows the phase order; any commit can be reverted in
isolation without affecting siblings.

If a phase makes dimensioning misbehave: `git revert <commit>` undoes it
cleanly. Phase D is the highest-risk; if it regresses picking or selection it
gets reverted before merging back to master.

## Done definition

- FA.FrameTiming reports `avg ≤ 11.1 ms` over a continuous-orbit sample with
  full quality settings (MSAA 4×, SSAO on, edges on, outline on).
- No visible stutter during orbit / pan / zoom.
- Dimension tool still works: face-select, point-select, dimension annotation
  renders correctly.
- Picking still works: tap selects the right mesh.
- Selection outline still works.
- Section planes still clip surfaces and edges correctly.
